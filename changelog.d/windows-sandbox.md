- 단말 서버 실행기가 Windows에서도 로컬 서버를 승인된 실행 계약대로 AppContainer 안에서 시작한다. 선언한 경로(와 실행 파일·스크립트 폴더, 패키지 실행기 캐시)에만 접근 권한을 더하고 서버가 끝나면 지우며(남은 권한은 다음 시작 때 정리), 서버는 작업 개체에 묶여 실행기와 함께 끝난다. 계약에 `network: none`을 선언한 서버만 네트워크가 막히며 `any`여도 같은 단말의 루프백에는 닿지 못한다. 관리형 설치는 AppContainer를 만들지 못하면 서버를 시작하지 않는다(`MINT_ENDPOINT_ALLOW_UNSANDBOXED`로 허용). 서버별 격리 상태 `appcontainer`가 추가됐고, 관리자 계정 Windows 보고기는 사용자 프로필을 읽지 않으므로 관리형 Windows 서버는 계속 「격리 미지원」으로 보고된다. `network: hosts`는 Windows에서 호스트별 거름을 집행하지 못해 인터넷 클라이언트 기능만 주고, 실행 기록·보고(`egress_unfiltered`)·실행기 출력과 경보 `endpoint_egress_unfiltered`로 알린다.
