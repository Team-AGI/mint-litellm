- 운영 자동화(마이그레이션 `031_automation`). (1) LiteLLM 제출로 도입 신청이 만들어지면 서버 주소의 호스트(제공자)와 도구 목록(허용 자원)을 미리 채우고 경보 `intake_pending`(웹훅 포함)으로 승인자에게 알린다. `intake create`의 `--allowed-resources`·`--provider`·`--owner`는 채워진 값이 있으면 생략한다. 승인은 그대로 사람이 한다. (2) 승인이 없어 `CALL_APPROVAL_REQUIRED`·`CALL_APPROVAL_STALE`로 막힌 호출은 같은 주체·서버·도구·인자의 대기 요청이 없을 때 호출별 승인 요청(24시간)을 대기 상태로 열고 작업 실행기가 경보 `call_approval_requested`와 요청 사건으로 알린다. 호출자 오류 본문에 `approval_requested`가 더해지며 결정 참조는 그대로이다(판정 프로세스에는 대기 요청 추가 권한만 더했고 승인·소비 전이는 그대로 막힌다). (3) 승인 만료 7일 전 경보 `approval_expiring`이 승인(`approvals`)에도 열리고, 콘솔 승인 화면에 계약·등급이 승인 뒤로 그대로인 승인을 모은 「일괄 갱신」(admin, CSRF)이 생겼다. 갱신은 같은 범위·도구·길이의 새 승인이며, 변경이 있는 승인은 사유와 함께 따로 나열된다. (4) 계약 변경 후보가 생기면 추가·삭제된 도구, 바뀐 입력 스키마 항목, 주소·인증 방식 변경을 한 줄로 적어 `contract_observations.change_summary`에 두고 계약 변경 화면에 보인다. 웹훅 안내 문구는 19종이 되었다.
