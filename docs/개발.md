# 개발 환경과 고정값

## 의존성 잠금

- 판본은 `uv.lock`이 고정한다. `pyproject.toml`에는 범위만 적고, 잠금 파일은 리눅스에서 만든다.
- 설치: `uv sync --locked --extra dev --extra litellm` (잠금과 `pyproject.toml`이 어긋나면 실패한다).
- 의존성을 바꾸면 `uv lock`으로 잠금을 다시 만들어 함께 커밋한다. 일부만 올릴 때는 `uv lock --upgrade-package <이름>`.
- CI는 `uv lock --check`로 잠금이 최신인지 먼저 확인한다.

## 이미지 고정

compose, Dockerfile, 시험 코드, CI 서비스에 쓰는 모든 이미지는 `이름:태그@sha256:<다이제스트>`로 쓴다. 대상은 PostgreSQL, 정책 엔진(OPA), LiteLLM, 파생 이미지의 Python 기본 이미지다.

갱신 순서:

1. 새 태그의 다이제스트를 레지스트리에서 조회한다: `docker buildx imagetools inspect <이름>:<태그>`의 `Digest` 줄(다중 플랫폼 이미지는 인덱스 다이제스트).
2. 같은 이미지를 쓰는 모든 곳을 함께 바꾼다. `git grep -n "sha256:"`로 위치를 찾는다. OPA는 `deploy/compose.yaml`, `deploy/Dockerfile.litellm`, `tests/unit/policy`의 두 시험이 같은 값을 쓴다. PostgreSQL은 `deploy/compose.yaml`과 `.github/workflows/ci.yml`이 같은 값을 쓴다.
3. 전체 시험과 `deploy/mint.sh up`으로 기동을 확인한다.

## CI 액션 고정

`.github/workflows/ci.yml`의 액션은 태그가 아니라 커밋 SHA로 쓰고, 뒤에 판본을 주석으로 적는다. 갱신할 때는 새 판본 태그가 가리키는 커밋 SHA를 조회해(`gh api repos/<소유자>/<저장소>/git/ref/tags/<태그>`, 주석 태그면 한 번 더 따라간다) 둘 다 바꾼다.

## 이미지 안 의존성

`deploy/constraints.txt`는 `uv.lock`에서 내보낸 판본 제약이고 파생 이미지가 `pip install -c`로 쓴다. 기반 이미지에 이미 설치된 패키지는 건드리지 않고(`deploy/merge-constraints.py`가 기반 목록을 먼저 고정한다) 새 패키지만 잠금 판본을 쓴다(제어 평면 이미지도 같은 이미지다). 의존성을 바꿔 `uv lock`을 다시 했으면 다음으로 다시 만들어 함께 커밋한다. CI는 같은 명령의 결과가 커밋된 파일과 같은지 확인한다.

```
uv export --frozen --no-dev --extra litellm --format requirements-txt --no-hashes --no-emit-project -o deploy/constraints.txt
```

## 통합 시험

`tests/integration`은 배포와 같은 파생 이미지(LiteLLM 복제본 2개), PostgreSQL, 정책 엔진, 공식 MCP SDK로 만든 시험용 MCP 서버 2대, 계수 역프록시, 장애 주입 프록시(Toxiproxy)를 한 스택으로 띄워 인수시험을 실행한다. 시험 서버는 시험 전용이며 배포 묶음과 승인 대상에 들어가지 않는다. 업스트림 호출 수는 계수 프록시의 접근 기록과 시험 서버의 도구 호출 진입 계수를 함께 대조하고, 0회를 판정하기 전에 같은 실행에서 양성 대조를 통과시킨다.

```
docker compose -p mint-e -f tests/integration/compose.yaml --profile plain up -d --build --wait
uv run pytest tests/integration
docker compose -p mint-e -f tests/integration/compose.yaml --profile plain down -v
```

- `plain` 프로필은 플러그인이 없는 LiteLLM 공식 이미지이다. 기반 동작 시험과 지연 비교에 쓴다.
- 스택이 떠 있지 않으면 통합 시험은 건너뛴다. 새로 띄운 스택에서 처음 실행해야 한다(첫 운영자와 정책을 만든다).
- 호스트가 `localhost` 대신 루프백 주소를 써야 하면 `MINT_E_HOST`로, docker를 다른 방식으로 부르려면 `MINT_E_COMPOSE`로 지정한다.
- 일부 시험은 두 복제본을 다른 설정으로 다시 띄운다. 시험 사이에 상태가 남으므로 시험 순서를 바꾸지 않는다.

## 엔드포인트 비용 비교

`tests/bench/endpoint_cost.py`는 같은 작업을 직접 실행(대조군)과 MINT를 거친 실행으로 돌려 성공률·오허용·오차단·효과 횟수·서버 시작 시간·판정 시간(p50·p95·p99)·철회 전파 시간·호출당 저장 증가를 한 JSON으로 낸다. 표준 라이브러리만 쓰며 단말(설치 묶음이 깔린 계정)에서 실행한다. 승인된 로컬 서버와 작업 파일(호출 목록, 호출마다 기대 판정과 효과를 남기는 파일)이 필요하고, 형식과 인자는 파일 머리말에 있다.

```
python tests/bench/endpoint_cost.py --workload work.json --agent ~/.mint/programs/mint_agent.py   --url https://<MINT 주소> --key-file ~/.mint/key --contracts ~/.mint/contracts.json   --state-dir ~/.mint/state --revoke-cmd '<권한을 거두는 명령>' --restore-cmd '<되돌리는 명령>'   --storage-cmd '<저장소 크기(바이트)를 출력하는 명령>' --output result.json
```

- 훅의 연결 재사용 효과는 같은 작업을 `--no-keepalive`를 주고 한 번, 주지 않고 한 번 돌려 `decision_ms`를 비교한다.
- 대조군은 판정이 없으므로 차단해야 할 호출이 모두 실행된다. 이 값이 MINT의 오허용 0과 맞서는 기준이다.
- 철회 전파는 `--revoke-cmd`가 끝난 시각부터 같은 호출이 막힐 때까지이며 `--revoke-timeout`(기본 120초) 안에 막히지 않으면 `propagated: false`이다.
