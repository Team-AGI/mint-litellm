# 승인된 읽기 요청의 재확인 재사용

기본값은 꺼짐이다. 기존 서버 도입 승인만으로 관리자 호출 승인이나 본인 확인이 생략되지는 않는다. 운영자가 새 사용자 승인을 만들 때 `approve --reuse-read-confirmations`를 명시한 경우에만 아래 절차가 적용된다. 기존 승인과 과거 호출 기록은 자동 전환하지 않는다.

## 적용 조건

- 관리형 서버의 승인된 도구 계약이 `action_type=read`, `risk_grade=low`이고 `url` 입력을 정의해야 한다.
- 승인은 사용자 범위(`--scope user`)여야 하며 `--allowed-host`로 정확한 목적지 호스트를 명시해야 한다. 와일드카드만으로는 재사용되지 않는다.
- 실제 호출 URL은 HTTP(S)이고 사용자 이름·비밀번호를 포함하지 않아야 한다.
- 입력 비밀 차단, 결과 검사, 별도 동의 의무, 시간대·목적지 제한은 계속 적용한다. 고위험 도구 지정, 실행·쓰기 작업과 임시 계약에는 적용하지 않는다.

관리자가 첫 호출을 승인하고 신청자가 본인 확인을 완료하면, 실제 허용 결정과 두 확인의 소비 기록이 같은 호출 식별자로 묶인다. 두 화면에는 동일 요청의 확인 기록을 재사용한다는 안내가 표시된다. 이후 동일 요청은 이 기록을 근거로 관리자 호출 승인과 본인 확인을 반복하지 않는다. 매번 정상 정책 검사를 거치며 새 감사 기록을 남긴다.

## 재사용 범위와 만료

사용자·API 키·조직·서버·도구·입력 인자 지문·도구 계약·정책 판본이 모두 같아야 한다. 동일 호스트라도 경로나 쿼리 등 인자가 바뀌면 새 확인이 필요하다. 인자 원문을 추가로 저장하지 않으며 기존 HMAC 지문을 비교한다.

재사용 기한은 사용자 승인 만료, 최초 허용 후 30일, 기간형 관리자 호출 승인의 만료 중 가장 이른 시각이다. 최초에 1회 승인을 선택해도 재사용 옵션과 화면 안내에 따라 이 범위의 재사용 근거가 된다. 기간형 승인을 사용하면 그보다 긴 권한으로 늘어나지 않는다.

사용자 승인 철회·만료·재인증 보류, 서버 상태·계약 변경, 정책 판본 변경, 키 변경 또는 원래 확인 기록 삭제 시 재사용되지 않는다. 새 허용 감사 기록을 쓰는 트랜잭션에서도 근거가 아직 유효한지 확인하며, 유효하지 않으면 차단한다. 프로세스 메모리 대신 DB 기록을 사용하므로 재시작 후에도 동일하게 동작한다.

## 운영 시 주의

이 기능은 도구의 위험 등급을 낮추지 않는다. 현재 계약이 `external_send/high`인 `browser_navigate`나 `read/medium`인 `browser_snapshot`은 자동 대상이 아니다. `url` 인자가 없는 현재 페이지 조회도 이번 구현 대상이 아니다. 브라우저에 적용하려면 목적지를 제한한 읽기 도구의 계약과 구현을 별도로 검토해야 한다. 이름만 보고 브라우저 전체를 저위험으로 분류하면 안 된다.

CLI에서 기존 승인 생성 인자에 `--reuse-read-confirmations`를 추가해 사용한다. 웹 콘솔에 이 옵션을 켜는 설정은 이번 변경에 포함하지 않는다. 저장된 조건이 켜진 승인의 최초 호출 승인·본인 확인은 기존 콘솔에서 처리할 수 있다. PaC 번들과 플러그인 코드를 함께 배포해야 하며, 저장소 pull만으로 실행 중인 VM에 반영되지는 않는다.
