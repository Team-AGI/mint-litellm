# MCP 서버 도입 신청 철회

신청자는 업무 변경, 중복 제출, 입력 오류로 불필요해진 승인 전 신청을 철회할 수 있다. 승인자가 본인 신청을 결정하지 못하도록 하는 직무 분리 정책은 그대로 유지한다.

직원은 **MCP 서버 도입 신청 → 본인 신청 상세**, 운영자는 **도입 신청 → 본인 신청 상세**의 **신청 철회**를 펼친다. 사유를 입력하고 확인란을 선택한 뒤 제출한다. POST에는 세션 인증, CSRF 검증, 신청 상태 버전이 필요하다. 신청자 식별자는 인증된 신원에서 가져오며 다른 사용자 식별자를 입력해 철회할 수 없다.

접수·검사 통과·판별 불가 상태의 본인 신청만 철회한다. 검사가 진행 중이거나 해당 검증 작업이 실행 중이면 완료 후 다시 시도한다. 이미 승인·예외 승인·거절로 결정된 신청은 철회할 수 없다. LiteLLM 제출 목록에서 유래한 `submission` 신청은 이 경로의 대상이 아니며 기존 제출 처리 절차를 사용한다.

철회는 `status=decided`, `decision=withdrawn`으로 기록된다. 기존 신청과 검사·증빙·감사 이력은 삭제하지 않는다. 현재 후보 계약은 종료하고, 미승인 서버의 연결 정보는 남긴다. 서버가 승인 대기 상태였다면 기존 재신청 가능한 미승인 상태인 `rejected`로 되돌리며, 신청의 결정 사유와 화면에는 철회로 표시한다. 처리되지 않은 검사 작업은 종료된 신청임을 확인하고 검사를 실행하지 않는다. 철회 후에는 같은 서버에 새 신청을 제출할 수 있다.

철회는 도구 사용 권한을 발급하지 않으며 이미 승인된 도입이나 사용 권한을 종료하는 절차를 대체하지 않는다. 자동 검사 실패로 이미 거절된 과거 신청은 그대로 보존한다.

DB 마이그레이션 `056_staff_intakes`와 `057_intake_withdraw`가 필요하다. 직원 DB 로그인에는 직접 UPDATE 권한이나 내부 철회 함수 실행 권한을 부여하지 않는다. 직원 전용 함수가 검증된 세션에서 신청자·인스턴스를 도출하고 본인 신청에만 변경을 허용한다. 변경과 `intake_decided` 감사 사건은 같은 트랜잭션에서 기록하며 중복 제출은 추가 사건 없이 기존 철회 결과를 반환한다.
