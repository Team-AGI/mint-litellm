# MINT for LiteLLM 제품 목표

## 한 줄 목표

LiteLLM을 쓰는 조직에서 MCP 서버를 **신청 → 검사 → 한 번 승인 → 배포 → 사용 → 사후 통제 → 회수**까지 한 제품에서 다룬다. 직원은 주소와 목적만 넣고 바로 쓰고, 관리자는 필요한 지점에서만 통제하며, Root Admin은 어느 단계에서든 즉시 멈출 수 있다.

완성의 기준은 기능이 코드에 있는 것이 아니다. 각 역할의 사용자가 **웹 화면과 PC 터미널에서 목적한 일을 오류 없이 끝낼 수 있어야** 완성이다.

## 사용자

| 역할 | 콘솔 역할 값 | 하는 일 |
|---|---|---|
| 직원(일반 사용자) | staff | MCP 서버 신청, 진행·검사 결과 확인, PC 연결, 승인된 서버·도구 사용, 거부된 도구 권한 요청, 내 사용 이력 |
| 승인자 | approver | 신청 승인·거부, 호출별 검토 |
| 관리자(일반·보안) | admin | 신청·검사 검토, 서버·도구·사용자 통제, 팀 권한, 정책 예외, 경보·감사 |
| Root Admin | root(admin의 상위) | 전역 강제 통제: 상태 강제 변경, 즉시 비활성화, 키·세션 폐기, 전역 정지 |
| 조회자 | viewer | 화면 보기만 |

## 지킬 설계 결정 (바꾸려면 CHANGE_PROPOSALS)

1. **구조**: LiteLLM 플러그인(호출 판정) + 제어 평면(작업 실행기) + 콘솔(FastAPI·Jinja) + PostgreSQL `mint` 스키마 + OPA 정책 묶음 + 직원 PC 키트(`mint`, 관리형 훅·실행기). MINT는 LiteLLM DB에 직접 접근하지 않고 LiteLLM API로만 쓴다.
2. **실행 위치**: 원격 MCP는 LiteLLM MCP 게이트웨이로, 로컬 MCP는 승인된 묶음을 직원 PC 실행기가 격리해 실행한다. 서버 쪽에서 로컬 MCP를 대신 실행하지 않는다.
3. **승인은 한 번**: 도입 심사 승인 한 번으로 서버 승인·범위·LiteLLM 등록·PC 허용 목록까지 끝난다.
4. **도구는 기본 통과, 사후 차단**: 승인된 서버의 도구는 새로 발견된 것까지 허용한다. 관리자가 서버·도구·사용자 단위로 막고, 해제하면 즉시 복귀한다. 호출별 검토는 관리자가 고른 도구에만 건다.
5. **입력 최소**: 신청은 주소(또는 실행 명령)와 목적만. 나머지는 제품이 채운다.
6. **가용성 우선**: 판정 서버 장애 때 이미 승인된 호출은 통과시키고 이후에 기록한다. 처음 보는 서버는 막는다.
7. **기본 관리자** root가 단독으로 모든 결정을 할 수 있다. 직무 분리는 선택 설정이다.
