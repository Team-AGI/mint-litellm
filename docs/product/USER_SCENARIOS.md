- 완료 조건: 앱 이름 1개만 입력하고 새 승인이 없으며 스크립트에 키·주소가 없고, 모델·원격 MCP 호출이 앱 키로 게이트웨이를 거치고 로컬 서버는 실행기가 중재한다.
- 관련 FM: FM-35 FM-29
- 관련 화면 동작: T6.run T6a.run T6b.run S11e.revoke S17a.revoke
- 상태: BACKEND_VERIFIED
- 증거 요약: Linux PC에서 환경 변수 주입·모델 목록 200, 회수 뒤 8초 안 401. 실제 모델 응답은 LiteLLM에 모델 공급자가 없어 미확인.

## 필수 E2E

소유자 지시로 아래 13단계를 하나의 연속 시험으로 통과해야 한다. 「커버」는 코드와 기능 명세로 확인한 현재 대응이며, 대응이 없으면 「기능 없음(신규 필요)」로 적는다. 시험은 GitHub 저장소로 등록한 서버 하나를 끝까지 써서 한 번에 돌린다.

공통: 상태 DISCOVERED는 연속 시험으로 통과한 적이 없다는 뜻이다. 단계별 대응 기능이 이미 개별 실측된 경우에만 괄호로 적는다.

### E2E-01 일반 사용자가 GitHub 저장소를 등록
- 커버: FM-37(저장소 주소 확인·미리보기·제출), FM-04, FM-47. 화면: 직원 신청 폼(S-staff_intake_new). PC `mint add 저장소주소`도 같다.
- 상태: DISCOVERED (FM-37은 IMPLEMENTED, 로그인 뒤 화면 제출 실측 전)

### E2E-02 관리자가 신청 목록에서 확인
- 커버: FM-04, FM-08. 화면: 「도입 신청」 목록 S02.open, 신청 상세.
- 상태: DISCOVERED (FM-04는 BACKEND_VERIFIED)

### E2E-03 관리자가 검수 후 승인
- 커버: FM-43(SBOM·SCA·SAST 검사 3줄), FM-46(재검사·권장 증빙), FM-06(S03.approve).
- 상태: DISCOVERED (FM-06 BACKEND_VERIFIED, FM-43 BACKEND_VERIFIED)

### E2E-04 MCP 서버가 실제로 등록·실행
- 커버: FM-06, FM-08(7단계), FM-49(PC 시작). 저장소 기반 서버(uvx/npx 커밋 고정)로 끝까지 돈 실측은 없다(PyPI·npm 서버만 FM-53).
- 상태: DISCOVERED

### E2E-05 일반 사용자가 그 서버를 쓸 수 있게 됨
- 커버: FM-10(PC 반영), FM-08, FM-09(팀 범위 승인), FM-42(내 서버 「준비 중」 카드).
- 상태: DISCOVERED (FM-10 BACKEND_VERIFIED)

### E2E-06 Claude Code에서 게이트웨이를 통해 도구 목록 조회
- 커버: FM-11(하네스 호출 기본 통과), FM-29(실행기 중재 tools/list). Codex·Gemini CLI·Windows PC 실측은 있으나 Claude Code로 목록을 조회한 기록은 시트에 없다.
- 상태: DISCOVERED (Claude Code 경로 실측 필요)

### E2E-07 실제 도구 호출
- 커버: FM-11, FM-29, 시나리오 U6·U13. 호출 기록은 S05 화면.
- 상태: DISCOVERED (FM-11 BACKEND_VERIFIED)

### E2E-08 권한 없는 도구는 적절히 거부
- 커버: FM-12(도구 차단), FM-19(거부 안내 첫 줄), FM-29(거부는 서버로 보내지 않음). 승인 범위 밖 서버·도구의 정책 거부 화면 안내도 FM-19.
- 상태: DISCOVERED (FM-12·FM-19 BACKEND_VERIFIED)

### E2E-09 사용자가 권한을 요청하고 관리자가 승인
- 커버: 부분. 막힌 호출이 있으면 게이트웨이가 호출별 승인 요청을 자동으로 열고(`plugin/approval_hold.py`, `control/services/expiry.py`의 자동 요청자), 관리자가 승인 센터 호출 승인 탭(`POST /call-approvals/{id}/approve`)에서 30분 승인하며, 직원은 「내 승인 요청」(`/staff/confirmations?tab=mine`)에서 읽기만 한다.
- **기능 없음(신규 필요)**: 직원이 화면에서 직접 「이 도구 권한 요청」을 내고 사유를 적는 흐름. 직원 화면에는 요청 양식이 없다. 호출별 승인 화면(S-approvals_calls) 자체도 기능 명세 FM에 속하지 않는다(UNMAPPED).
- 상태: DISCOVERED

### E2E-10 승인 뒤 정상 사용
- 커버: FM-19(승인 대기 안내), 승인 센터 호출 승인 후 같은 호출 재개(`approval_hold`). 기능 명세에 등록되지 않은 동작이라 FM 신규 등록이 필요하다.
- 상태: DISCOVERED

### E2E-11 Root Admin이 실행 중인 서버를 비활성화
- 커버: FM-14(서버 「중지」 `POST /servers/{id}/suspend`), FM-45(이용 종료), FM-32(단말 단위 중지).
- 상태: DISCOVERED (FM-14 BACKEND_VERIFIED)

### E2E-12 기존 권한·세션이 무효화
- 커버: FM-14(중지 직후 호출 즉시 거부), FM-09(팀 이탈 시 권한 회수), FM-53(폐기 뒤 2분 안 차단·제거). 이미 열린 하네스 세션이 중지 후 계속 도구를 쓰지 못하는지의 연속 시험은 없다.
- 상태: DISCOVERED

### E2E-13 재접속·재실행 때도 통제 유지
- 커버: FM-10(PC가 20초마다 보고하고 서명 갱신), FM-30(결정 서버 장애 중에도 폐기 서버 차단), FM-53(폐기 뒤 PC가 서버를 시작하지 않음). 재접속·재실행 자체를 시나리오로 묶은 기능·시험은 없다.
- 상태: DISCOVERED
