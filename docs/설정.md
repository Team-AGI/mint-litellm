# 설정

MINT가 읽는 설정과 LiteLLM에 요구하는 설정을 정리한다. `mint-litellm init`이 이 표의 값을 LiteLLM 설정 조각으로 만들고, `mint-litellm check`가 같은 표로 설정 파일과 관리 API를 검사하며, 플러그인은 기동 후 같은 표로 자가 점검을 수행한다.

## 1. MINT 설정의 우선순위

| 키 | 출처 | 규칙 |
| --- | --- | --- |
| `MINT_MODE` | 환경 변수 | 모드 상한. enforce이면 저장된 설정이 observe로 바꿀 수 없다. |
| `settings.mode` | 데이터베이스 | 상한 이하에서만 설정한다. 변경은 사건을 남기고 세대를 올린다. |
| `settings.observable_reasons` | 데이터베이스 | 관측 모드로 전환할 수 있는 사유 계열의 부분집합. 기본값은 전환 후보 전체. |
| `settings.observable_policy_ids` | 데이터베이스 | 관측 가능으로 선언된 정책 중 관측에 쓸 정책 식별자. |
| `settings.default_org_id` | 데이터베이스 | 팀·사용자 바인딩이 없는 주체에 적용할 기본 조직. 해제할 수 있다. |
| `MINT_REQUIRED` | 환경 변수 | 기본 true. 자가 점검 실패 시 프록시 기동을 중단한다. |
| `MINT_HIGH_RISK_TOOLS` | 환경 변수 | 호출별 승인을 요구할 고위험 도구 목록. 저장된 설정으로 덮지 않는다. |
| `MINT_TARGET_PROFILES` | 환경 변수 | 원격 서버의 호출 대상·행위 프로필을 덮어쓴다(`서버 식별자=프로필` 쉼표 목록, 프로필은 `github`·`n8n`·`none`). 기본은 승인된 배포 계약에서 자동으로 고른다. 저장된 설정으로 덮지 않는다. |
| `MINT_DECISION_BUDGET_MS` | 환경 변수 | 판정 하나의 시간 예산(밀리초, 기본 300). 상태 조회·정책 평가·선기록은 남은 시간만큼만 기다리고, 시간 초과는 결과 불명으로 다룬다. 데이터베이스가 응답하지 않아도 이 시간에서 끝나며(서버 쪽 잠금 제한 `lock_timeout`은 같은 값, 문장 제한 `statement_timeout`은 열 배, 연결 시도 제한도 건다. 이 제한은 연결 시작 매개변수로 걸리므로 트랜잭션 모드 연결 풀러를 거치지 않고 Postgres에 직접 붙인다), 상태 조회가 넘으면 `MINT-DEPENDENCY-DB`로 차단한다. 저장된 설정으로 덮지 않는다. |
| `MINT_LOG_LEVEL` | 환경 변수 | 플러그인 로그 수준(DEBUG, INFO, WARNING, ERROR). 정하지 않으면 로그 설정을 바꾸지 않는다. DEBUG이면 도구 호출 판정마다 `decision_ms=<밀리초> ref=<판정 참조> allowed=<true|false>` 한 줄을 표준 오류에 남기고, 그 뒤에 단계별 시간(`hook_ms`, `snapshot_ms`, `markers_ms`, `input_ms`, `patterns_ms`, `fingerprint_ms`, `policy_ms`, `event_ms`)과 입출력 대기 횟수(`awaits`)가 붙는다. 시간은 판정 진입부터 반환까지이고 선기록을 포함한다. 응답을 받은 호출은 `response_ms=<밀리초> ref=<판정 참조> revocation_ms=<밀리초> event_ms=<밀리초>` 한 줄도 남긴다. DEBUG가 아니면 시간을 재지 않는다. |
| `MINT_LIST_DEDUP_SECONDS` | 환경 변수 | 도구 목록에서 「보임」으로 통과한 판정은 같은 주체·서버·도구가 같은 상태 세대·설정 판본·정책 판본이면 이 시간(기본 86400초) 안에는 다시 기록하지 않는다. 0이면 목록마다 기록한다. 숨김·차단·관측 모드의 걸림은 언제나 기록한다. 기억은 워커 프로세스 메모리에 있고(최대 10만 키) 프로세스가 다시 뜨면 한 번씩 다시 기록된다. |
| `MINT_DEFAULT_MAX_RESULT_BYTES`·`MINT_DEFAULT_MAX_RESULT_ITEMS` | 환경 변수 | 계약 관리 서버의 승인 조건에 `max_result_bytes`·`max_result_items`가 없을 때 채우는 결과 상한(기본 1048576바이트·1000항목). 승인에 적은 값이 우선하고, 0이면 그 상한은 채우지 않는다. 상한을 넘은 결과는 호출자에게 주지 않고 `MINT-OUTPUT-BLOCKED`로 바꾼다(POL-E-16). |
| `MINT_ALLOW_REALTIME` | 환경 변수 | 기본 false. 실시간 경로(`/v1/realtime*`) 요청을 `MINT-REALTIME-FORBIDDEN`으로 막는다. true로 명시해야 허용하며, 연결 뒤 `session.update`의 도구는 MINT가 판정하지 못한다. `enable_openai_websocket_passthrough`가 켜진 LiteLLM 설정은 이 값을 true로 명시하지 않으면 자가 점검이 실패한다(보장과-한계 참조). |
| `MINT_ALLOW_UNTESTED_LITELLM` | 환경 변수 | 기본 false. 시험하지 않은 LiteLLM 판본은 모든 훅 능력이 감지되어도 기동을 거부한다. true로 명시하면 기동하고 `mint status`에 「검증되지 않은 판본」으로 표시한다(보장과-한계 1-1 참조). |
| `MINT_ALLOW_CODE_EXECUTION` | 환경 변수 | 기본 false. 모델 생성 코드를 LiteLLM 샌드박스에서 실행하는 요청(`container`, 코드 인터프리터·코드 실행 도구)을 `MINT-CODE-EXECUTION-FORBIDDEN`으로 막는다. `code_interpreter_interception`이 켜진 구성은 이 값을 true로 명시하지 않으면 자가 점검이 실패한다(보장과-한계 참조). |
| `MINT_ENDPOINT_ROUTES` | 환경 변수 | 기본 false. true이면 LiteLLM 앱에 단말 훅용 경로 `POST /mint/v1/decide`(호출 전 판정)와 `POST /mint/v1/result`(호출 뒤 결과 보고)를 붙인다. 호출자 키로 인증하며 신원은 인증 객체에서만 얻는다. 결정 요청은 등록된 로컬 서버의 식별자와 실행 계약을 보내고, 계약의 해시는 MINT가 계산해 서버 행과 비교한다. 결과 보고는 그 판정을 만든 키만 보낼 수 있고 `success`·`error`·`unknown`만 받는다(결과 본문은 받지 않는다). 보고가 5분 안에 없는 허용 호출은 작업 실행기가 `call_outcome_unknown`(사유 `no_report`)으로 남긴다. 설치 묶음이 설치·제거를 마치고 보내는 상태 보고 `POST /mint/v1/endpoint/report`도 붙으며, 설치 묶음에 발급한 해제되지 않은 키의 보고만 `endpoint_installs`에 남기고(관리형·사용자 수준·제거됨, 설치된 판본과 서버 목록) 그 밖의 키는 404로 거부한다. 키가 만료되었으면 403(`kit key expired`)으로 거부하고, 만료 14일 안에 들어온 보고는 키의 만료 시각을 유효 기간만큼 늘린다(응답의 `renewed`). |
| `MINT_KIT_ISSUER_KEY` | 환경 변수 | 콘솔의 직원 화면 「단말 설치」가 사용자 키를 발급할 때 쓰는 LiteLLM 키. 이 키의 `allowed_routes`는 `/key/generate`와 `/key/delete`만 열어 둔다. 발급하는 키는 사용자 한 명의 키이며 `allowed_routes`가 `/mint/v1/decide`·`/mint/v1/result`·`/mint/v1/endpoint/report`뿐이고, 새 설치 묶음을 내려받으면 같은 사용자의 이전 키는 지워진다. `./mint.sh up`·`upgrade`가 비밀 폴더(`MINT_SECRETS_DIR`)의 `kit_issuer.key`가 없을 때만 마스터 키로 이 키를 만들어 두고 콘솔에 넘긴다(있으면 그대로 쓰고, 만들지 못하면 경고만 하고 기동을 계속한다). 설정하지 않으면 설치 묶음을 내려받을 수 없다. |
| `MINT_ENDPOINT_KEY_DAYS` | 환경 변수 | 새로 발급하는 단말 설치 묶음 키의 유효 기간(일, 30~365). 기본 90. 설치한 단말은 6시간마다 설치 상태를 보고하고, 만료 14일 안에 들어온 보고가 만료 시각을 같은 기간만큼 늘리므로 보고하는 단말의 키는 만료되지 않는다. 만료된 키는 보고가 거부되며 직원 화면에서 묶음을 다시 내려받아 설치하면 새 키가 발급된다. 만료까지 7일 이하인 키는 경보 `endpoint_key_expiring`을 연다. |
| `MINT_ENDPOINT_SILENT_HOURS` | 환경 변수 | 설치 보고가 이 시간(시) 넘게 없는 단말에 경보 `endpoint_silent`를 연다. 기본 24. 보고가 다시 오면 닫힌다. 제거 보고와 보고한 적 없는 행은 제외한다. |
| `MINT_ENDPOINT_PUBLIC_URL` | 환경 변수 | 설치 묶음에 적는, 단말이 판정 경로를 부르는 주소. 정하지 않으면 `MINT_LITELLM_URL`을 쓴다. |
| `MINT_ENDPOINT_CA_FILE` | 환경 변수 | 판정 경로가 사설 인증 기관의 인증서를 쓸 때 설치 묶음에 함께 넣는 인증 기관 파일(PEM). 읽을 수 없으면 콘솔이 기동하지 않는다. |
| `MINT_SHADOW_OPA_URL` | 환경 변수 | 정책 시험 적용용 정책 엔진 주소. 비우면 시험 판본을 읽지도 평가하지도 않는다. 값이 있으면 워커가 5초마다 시험 판본을 확인하고, 있을 때만 호출마다 활성 판본의 판정이 끝난 뒤 같은 입력을 시험 판본으로 평가해 판정이 달라지는 호출만 센다. `MINT_SHADOW_SAMPLE_PERCENT`(기본 100)와 `MINT_SHADOW_MAX_PER_SECOND`(워커당, 기본 50)가 평가 비율과 초당 상한이며 동시에 진행하는 평가는 16건까지다. |
| `MINT_GC_FREEZE` | 환경 변수 | 기본 true. 워커의 자가 점검이 통과하면 그때까지 만들어진 객체를 가비지 수거 대상에서 빼서(`gc.freeze()`) 가장 오래된 세대의 수거가 이벤트 루프를 0.5~1초 멈추는 일을 막는다. 얼린 객체는 이후 수거되지 않으므로 워커 메모리가 기동 때의 쓰레기만큼 늘 수 있다. LiteLLM 프로세스 전체의 설정이라 다른 확장과 충돌하면 false로 끈다. |
| `MINT_SELFCHECK_GRACE_SECONDS` | 환경 변수 | 기동 뒤 준비 상태와 자가 점검 8항목을 마쳐야 하는 시간(초, 기본 120, 범위 10~600). 범위 밖이면 기동을 거부한다. 시간 안에 마치지 못하면 사건을 남기고, `MINT_REQUIRED=true`이면 기동을 중단한다. |
| `MINT_FINGERPRINT_KEY` | 환경 변수 | 호출별 승인 인자 지문의 키(32바이트 이상 무작위 값의 base64url). `init`이 만들어 저장소 밖 비밀 파일(권한 0600)에 기록한다. 호출별 승인의 인자 지문을 계산하는 데 쓰이므로 필수이며, 없으면 자가 점검이 실패해 기동을 중단한다. |
| `MINT_FINGERPRINT_KEY_VERSION` | 환경 변수 | 지문 키의 판본(1 이상 정수, 기본 1). 승인에 기록된 판본과 다르면 호출별 승인이 다시 필요하다. |

환경 변수로 정한 값은 데이터베이스로 덮어쓸 수 없다. 모드와 관측 설정을 바꾸면 사건이 기록되고 상태 세대가 올라간다.

### 인자 지문 키의 교체

호출별 승인은 인자 지문(키 정렬 JSON의 HMAC-SHA256)과 키 판본을 함께 기록한다. 키를 바꿀 때는 새 키와 함께 `MINT_FINGERPRINT_KEY_VERSION`을 올리고, 프록시와 `call-approval request`를 실행하는 운영자 명령 환경에 같은 값을 넣는다. 프록시는 모든 워커와 복제본을 재기동해 새 값이 적용됐는지 확인한다. 이전 값으로 남은 워커에서는 이전 승인이 계속 유효하기 때문이다. 그다음 교체 전에 만들어져 아직 소비되지 않은 호출별 승인을 다시 요청한다. 이 승인들은 판본이 달라 새 값을 쓰는 워커에서 충족되지 않는다.

### 호출 대상·행위 결속

서버의 승인된 배포 계약에서 알려진 프로필(`github`, `n8n`)을 자동으로 고른다. 계약의 URL 호스트가 프로필의 호스트와 같거나, 승인된 도구 이름(배포 계약의 허용 도구와 승인된 도구 계약) 중 프로필의 서명 도구가 둘 이상이면 그 프로필이다. 근거가 없거나 두 프로필에 모두 맞으면 고르지 않는다. 프로필이 정해진 서버로 가는 호출은 인자에서 구조적으로 뽑은 대상과 행위에 묶이고, 프로필이 없는 서버의 동작은 바뀌지 않는다. `MINT_TARGET_PROFILES=<서버 식별자>=<프로필>[,...]`는 자동 선택을 덮어쓰는 용도이며 `none`이면 그 서버의 결속을 끈다. 선택 결과(프로필과 출처 `auto`·`config`)는 판정 사건의 `target_profile`·`target_profile_source`와 `check`의 `호출 대상 프로필` 항목에 나온다.

- GitHub: 대상은 `owner/repo`(소문자로 비교), 행위는 도구 이름과 `method`이다. 워크플로 실행 등 `actions_run_trigger`는 실행으로 본다.
- n8n: 대상은 `인스턴스/워크플로 ID`이다. 인스턴스는 호출의 `instance` 인자이고, 없으면 호출이 향한 서버이다. 행위는 도구 이름과 하위 방식이며, 빠진 인자에는 서버의 실제 기본값을 적용한다(예: `n8n_test_workflow`의 `method`는 `auto`이고 `auto`는 워크플로를 실행한다. `prepare`만 읽기이다).
- 읽기가 아닌 효과(변경·실행)는 정책이 따로 요구하지 않아도 호출별 승인이 있어야 하고, 승인은 받은 때의 대상·행위와 완전히 같은 호출에만 쓰인다. 소비 때도 같은 조건으로 다시 대조한다. 대상이 다르거나 행위가 다르면 업스트림으로 보내기 전에 차단한다.
- 프로필에 없는 도구, 필수 대상 인자가 빠졌거나 평범한 식별자가 아닌 변경·실행 호출은 승인으로 풀 수 없으므로 `CALL_APPROVAL_REQUIRED`로 차단한다. 읽기만 하는 도구는 대상을 정하지 못해도 막지 않는다.
- `call-approval request`는 같은 선택 규칙(덮어쓰기를 쓴다면 같은 `MINT_TARGET_PROFILES`를 운영자 명령 환경에 둔다)을 적용하며 `--arguments` 또는 `--args-file`로 요청해야 한다(`--args-fp`만으로는 대상을 정할 수 없어 거부한다). 대상과 행위는 승인 행에 기록되며, 값이 없는 이전 승인은 프로필이 켜진 서버에서 맞지 않는다.
- 판정 사건에 `bound_target`·`bound_action`을 남기고, 레지스트리가 알려 주는 원격 자격 주체를 `resolved_credential_ref`로 남긴다(고정 토큰은 지문만, OAuth는 클라이언트 식별자. 호출자별 자격은 훅에서 보이지 않아 비어 있다).

## 2. 자가 점검

플러그인은 기동 직후 모든 MCP 호출과 공급자 쪽 MCP가 담긴 모델 요청을 차단한 상태로 시작하고, 워커 프로세스마다 아래 8개 항목을 프로세스 안에서 확인한 뒤에만 호출을 받는다. 하나라도 실패하면 사건(`enforcement_unverified`)을 남기고 프록시 기동을 중단한다(`MINT_REQUIRED=true`, 기본값). 중단한 컨테이너는 종료 코드 3으로 끝난다(가드레일·로거 생성자가 구성 오류로 실패해 기동을 못 마칠 때도 같다). 워커가 여럿이면(`--num_workers`) LiteLLM의 감독 프로세스는 워커의 종료 코드와 무관하게 0으로 끝나므로, 워커가 남기는 표식(`MINT_EXIT_CODE_FILE`)을 컨테이너 진입점이 읽어 3으로 바꾼다. 진입점을 거치지 않고 LiteLLM을 직접 시작하면 이 변환이 없다. 표식은 기본으로 `/tmp/mint-exit-code`에 쓰므로, 그 경로에 쓸 수 없는 구성(읽기 전용 루트 파일시스템 등)에서는 변환이 일어나지 않는다. `MINT_EXIT_CODE_FILE`은 진입점이 기동 때 지우는 이 용도 전용 경로로 둔다. 자가 점검을 마치기 전(유예 시간 안)에 만든 가드레일·로거가 실패하거나 `MINT_REQUIRED=false`에서 점검에 실패한 채 계속 도는 워커가 있으면 표식이 남아, 그 컨테이너가 이후 정상으로 멈춰도 3으로 끝날 수 있다. 모두 통과하면 워커마다 사건 `enforcement_verified`를 한 번 남긴다(점검 항목별 결과 포함). 기동 점검에 실패했던 워커(`MINT_REQUIRED=false`)가 이후 통과할 때도 한 번 남긴다. 플러그인은 LiteLLM 키나 관리 API를 쓰지 않으며, `check`가 같은 항목을 설정 파일과 관리 API로 다시 검사한다.

| 번호 | 항목 |
| --- | --- |
| 1 | MINT 로거가 정확히 하나 등록되어 있다. |
| 2 | MINT 가드레일이 세 모드(`pre_call`·`pre_mcp_call`·`post_mcp_call`)로 등록되어 있고 `default_on`이다. 모드가 하나라도 빠지면 집행을 확인하지 못한 것으로 보고 기동을 멈춘다. |
| 3 | MINT 가드레일이 하나이고, 병렬 실행·원문 검사 끔·판정 재정의(클래스와 인스턴스 모두)가 그대로이다. |
| 4 | 통제 서버가 `allow_all_keys: false`이고 `require_key_mcp_access_defined`가 true이다. |
| 5 | 승인된 통제 서버의 `server_id`가 레지스트리에 있다. 계약 값(URL 해시·전송 방식·인증 방식)이 다르면 기동은 계속하고 사건으로 남기며, 그 서버의 호출은 차단한다. 중지된 서버가 레지스트리에 없으면 기동은 계속하고 사건(`registry_missing`)으로 남긴다. |
| 6 | 설정과 DB를 합친 서버의 이름·별칭이 전역에서 유일하다. |
| 7 | 호환 계층이 쓰는 LiteLLM 비공개 심볼이 모두 존재한다. |
| 8 | 필수 설정 행이 모두 표의 값과 일치한다. |

## 3. LiteLLM 설정

등급의 의미는 다음과 같다.

- **필수**: 어긋나면 자가 점검이 실패해 기동이 중단되고 `check`도 실패한다.
- **권장**: `check`가 경고한다.
- **관측**: `status`와 `check`가 값을 표시하며 실패 조건이 아니다.

통제 대상 설정 서버의 `server_id` 명시 여부는 프로세스 안에서 원본 설정을 읽을 수 없으므로 `init`과 `check`의 설정 파일 검사로만 확인한다. 프로세스 안에서는 자가 점검 5번이 해당 `server_id`가 레지스트리에 존재하는지를 대신 확인한다. 계약 값(URL 해시, 전송 방식, 인증 방식)이 다르면 기동은 계속하고 사건으로 남기며, 그 서버의 호출을 차단한다. 그 외의 필수 행은 모두 자가 점검 항목에 대응한다.

| 키 | 위치 | 값 | 등급 | 자가 점검 | 이유 |
| --- | --- | --- | --- | --- | --- |
| `guardrails[MINT]` | `guardrails` | mode: [pre_call, pre_mcp_call, post_mcp_call], default_on: true | 필수 | 2, 3 | 가드레일이 없으면 도구 호출 판정과 도구 목록 필터가 사라지고, pre_call이 없으면 공급자가 외부 MCP 서버를 직접 부르는 모델 요청을 막지 못한다. |

LiteLLM이 구현하는 정책은 위 필수 행으로 설정 값을 강제해 이행으로 센다. 통제 서버(자가 점검)와 설정 파일의 서버(`check`·기동 전 검사)에 같은 규칙을 쓰며, `check`는 정책마다 충족 여부 한 줄을 보인다. `init --fix-config`는 빠진 `disable_env_credential_login: true`와, 서버마다 빠진 `rpm: 600`·`max_concurrent_requests: 8`과, LiteLLM이 토큰을 받는 OAuth 서버(`auth_type: oauth2`)의 `upstream_resource: auto`를 설정에 더한다(resource를 거부하는 인가 서버는 빈 문자열로 적어 끈다)(이미 적힌 값은 그대로 둔다). 키·팀별 `mcp_rpm_limit`은 운영자 선택이다. 서버 사이 자격 공유 점검은 `authentication_token`과 클라이언트 자격 외에 정적 헤더(`static_headers`)에 적은 Authorization·API 키류 헤더 값도 비교한다. LiteLLM DB에 등록된 서버의 빈 `rpm`·`max_concurrent_requests`는 서버 승인과 주기 동기화 때 MINT가 600·8로 쓰고(운영자가 적은 값은 덮지 않음) 사건으로 남기며, 쓰지 못하면 경보를 올리고 다음 동기화에서 다시 시도한다.

| --- | --- |
| `spend_log_arguments_stored` | `disable_spend_logs`가 참이 아니면 `true`. 도구 호출 인자가 LiteLLM 지출 로그에 저장된다. |
| `guardrail_optout_subjects` | 다른 가드레일을 끈 키·팀의 수. 관측 항목이며 실패 조건이 아니다. MINT 판정과 도구 목록 숨김은 이 키·팀에도 그대로 적용된다. |
| `unbound_keys` | 사용자와 팀 어디에도 결속되지 않은 키의 수. 0이 아니면 `check`가 경고한다. |
| `auth_cache_shared` | 복제본 사이에 키·팀 권한 캐시를 공유하는지(공유 Redis 설정 여부). |

## 5. 제어 평면의 LiteLLM 키

제어 평면과 CLI는 LiteLLM 데이터베이스를 직접 읽거나 쓰지 않고 관리 API의 읽기 경로만 쓴다. 이를 위해 `proxy_admin` 사용자 키 하나를 발급하고 `allowed_routes`를 아래 최소 목록으로 제한한다. 정확히 일치하거나 `경로/` 접두사로 시작하는 요청만 허용되며 `/mcp`, `/mcp-rest/*`, `/key/generate`는 닫힌다.

- `/v1/mcp/server`
- `/key/info`
- `/team/info`
- `/user/info`
- `/key/list`
- `/team/list`
- `/user/list`
- `/guardrails/list`
- `/key/update`
- `/team/update`

`/key/update`와 `/team/update`는 권한 동기화가 키·팀의 `object_permission`을 쓸 때만 쓴다(본문은 대상 식별자와 `mcp_servers`·`mcp_tool_permissions`뿐이다). LiteLLM은 갱신 필드를 제한하지 못하므로 이 키가 유출되면 키·팀의 모든 설정을 바꿀 수 있고, 작업 실행기와 명령줄에만 둔다.

관리 API 응답의 자격 열(`credentials`, `static_headers`, `env_vars`, `credential_b64`, `mcp_user_credentials`)은 수신 즉시 버리며 저장·기록·표시하지 않는다.

## 6. 데이터베이스

MINT 상태와 원장은 PostgreSQL 15 이상의 `mint` 스키마에 저장한다. 초기 스키마는 `control/db/migrations/001_initial.sql`이다. 스키마가 만드는 로그인 불가 그룹 역할을 프로세스별 로그인 역할에 부여해 쓴다.

| 역할 | 권한 |
| --- | --- |
| `mint_plugin` | 판정 프로세스용. 상태 표 조회, 원장 추가·조회, 승인된 호출별 승인을 소비하는 전이(승인됨에서 소비됨)만 수정할 수 있다. 운영자 표는 읽을 수 없다. |
| `mint_control` | 제어 평면용. 상태 표 조회·추가·수정, 조직 바인딩 삭제, 원장 추가·조회. 세대 표는 읽기만 가능하다. |
| `mint_ledger_writer` | 원장 추가·조회. 위 두 역할이 포함한다. |
| `mint_sealer` | 원장 조회와 봉인 열 채우기만 가능하다. |

상태 세대는 집행에 영향을 주는 표가 바뀔 때마다 같은 트랜잭션에서 데이터베이스 트리거가 올린다. 원장은 추가만 가능하다. 삽입할 때 봉인 열은 항상 비워지고, 봉인 열을 한 번 채우는 수정 외에는 수정·삭제·비우기가 모두 거부된다. 사건은 같은 배치에서 `source_key`가 같으면 한 행으로 수렴한다.

플러그인은 LiteLLM 워커 프로세스마다 `MINT_DB_POOL_SIZE`(기본 4)개의 연결을 처음 열 때 모두 만들어 두고 줄이지 않는다. 플러그인이 쓰는 연결 수는 `MINT_DB_POOL_SIZE` × LiteLLM 워커 수이며(`--num_workers`), LiteLLM·제어 서버·작업 실행기·콘솔·관리 접속의 연결은 따로 센다. 이 합이 Postgres `max_connections`에 여유를 남기도록 풀 크기나 워커 수를 정한다. 연결이 모자라면 연결을 만들지 못해 호출이 `MINT-DEPENDENCY-DB`로 차단된다.

### LiteLLM 워커 수

컨테이너당 워커 수는 `MINT_LITELLM_WORKERS`(기본 2)이고 compose가 LiteLLM의 `NUM_WORKERS`로 넘긴다. 워커는 프로세스마다 이벤트 루프를 따로 가진다. LiteLLM은 호출 하나에 CPU를 수십 밀리초 쓰므로(MCP 카탈로그 복사, 업스트림 연결, 기록), 워커가 하나이면 동시 호출이 한 루프에 줄을 서고 판정의 모든 대기(상태 조회, 정책 평가, 사건 기록)가 그 줄 뒤에서 늘어난다. 워커를 둘로 늘리면 같은 부하에서 판정 지연이 크게 줄어든다.

- 메모리: 워커마다 약 0.8GiB(LiteLLM 적재 크기)다. 컨테이너당 워커 수 × 복제본 수 × 0.8GiB를 확보한다.
- DB 연결: 플러그인 연결은 `MINT_DB_POOL_SIZE` × 워커 수 × 복제본 수, LiteLLM 자체 연결은 워커마다 쓰기 10개(LiteLLM이 기동할 때 이 합을 출력한다)다. 기본값(풀 4, 워커 2)은 컨테이너당 플러그인 연결 8개로 워커 1개·풀 8과 같다. 이 합과 제어 서버·작업 실행기·콘솔·관리 접속의 연결이 `max_connections`에 여유를 남겨야 한다.
- 자가 점검은 워커마다 따로 돌고 통과한 워커만 호출을 받는다.
- 키·팀 권한 캐시는 워커마다 메모리에 있다. 복제본 × 워커가 둘 이상이면 `enable_redis_auth_cache`와 공유 Redis가 필요하며, 없으면 `check`가 경고한다(`MINT_REPLICAS`, `MINT_LITELLM_WORKERS`).
- 워커 1개로 돌리려면 `MINT_LITELLM_WORKERS=1`, `MINT_DB_POOL_SIZE=8`로 둔다.

## 7. 정책 엔진 배치

정책 엔진은 번들 모드로 띄우고 번들 파일을 감시한다.

```
opa run --server --addr :8181 --bundle --watch /bundles/mint.tar.gz
```

- `--bundle` 없이 타르볼만 감시하면 재적재 때 이전 파일과 새 파일이 서로 다른 경로로 함께 남아 같은 기본 규칙이 중복되어 적재가 실패한다.
- 번들 디렉터리는 정책 엔진과 제어 평면 컨테이너가 공유하는 리눅스 파일시스템의 명명 볼륨이어야 한다. 호스트 디렉터리 바인드 마운트(특히 Windows 호스트의 경로)는 파일 변경 알림이 전달되지 않아 감시 재적재가 일어나지 않는다.
- `policy activate`는 번들을 같은 디렉터리의 임시 파일에 쓴 뒤 이름을 바꿔 게시하고, 정책 엔진이 새 판본을 적재해 응답할 때까지 확인한 다음에만 판본을 활성으로 전환한다. 제한 시간 안에 확인하지 못하면 판본은 활성화되지 않으며 같은 명령으로 다시 시도할 수 있다.
- 정책 엔진은 번들 파일이 있어야 기동한다. 배포 묶음의 `mint.sh up`이 첫 번들을 게시한다.

### 정책 입력 계약

정책 입력은 `src/mint_litellm/plugin/policy/input.py`가 허용한 항목만 정책 엔진에 보내며, 입력 계약의 판본은 정책 번들의 판본(`policy activate`로 활성화한 판본)과 함께 움직인다. 입력 항목을 읽는 규칙이 바뀐 번들을 활성화하기 전에는 그 항목이 판정에 쓰이지 않는다.

- `server.contract_status`: `none` 또는 `managed`(계약 관리 서버). 항상 보낸다. 빠지거나 다른 값이면 패턴 규칙이 건너뛰어지지 않도록 입력 오류로 차단한다. 새 번들은 이 항목을 필수로 보므로 플러그인을 먼저 올린 뒤 번들을 활성화한다(이전 플러그인은 이 항목을 보내지 않아 새 번들에서 모든 호출이 입력 오류로 차단된다).
- `server.identity_kind`: `remote`(URL로 접속하는 서버) 또는 `stdio`(로컬 실행 서버). 항상 보낸다. 새 번들은 이 항목을 필수로 보므로(빠지거나 다른 값이면 입력 오류로 차단) 플러그인을 먼저 올린 뒤 번들을 활성화한다.
- `server.exec_contract_sha256`·`server.exec_contract_version`: `stdio` 서버에서만 보낸다(실행 계약의 해시와 계약 스키마 판본). 원격 서버에는 키가 없다. 로컬 서버는 URL 해시를 갖지 않고 이 두 값으로 승인본과 대조한다. `stdio`에서 해시가 없거나 64자리 소문자 16진수가 아니면 입력 오류로 차단한다.
- `server.exec_approved_sha256`: `stdio` 서버 행에 등록된 승인 대상 실행 계약의 해시. 서버 행이 없거나 승인 상태가 아니거나 이 값이 없으면 규칙 POL-R-18이 막고, 보고된 `server.exec_contract_sha256`과 다르면 규칙 POL-R-20이 막는다. 두 해시는 MINT가 계산한 값이며 단말이 보낸 일치 여부는 입력으로 받지 않는다.
- `arguments.patterns`: 계약 관리 서버에서는 필수(네 패턴 불리언 전부). 없거나 깨지면 입력 오류로 차단한다. 1단계 서버는 보내지 않는다.
- `tool.name`: 호출한 도구 이름.
- `tool.action_type`: 계약 관리 서버에서 지금 승인된 도구 계약의 행위 유형(`read`·`write`·`delete`·`external_send`·`credential_access`). 계약이 없으면 키가 없다. 번들 규칙이 아직 이 항목을 읽지 않으므로 플러그인과 번들을 올리는 순서는 상관없다.
- `approval.conditions`: 저장된 승인 조건에 MINT가 빠진 집행 조건(허용 인자 키, 삭제·외부 전송 도구의 본인 확인 대상, 기밀 이상 자료 서버의 동의)을 채운 값이다. 승인 행은 바뀌지 않는다.
- `tool.risk_grade`: 계약 관리 서버에서 지금 승인된 도구 계약의 위험 등급(`low`·`medium`·`high`·`critical`). 승인된 계약이 없으면 키가 없고, 계약이 있는데 등급이 비어 있거나 네 값이 아니면 입력 오류로 차단한다. `high`·`critical`이면 승인이 어떤 경로로 만들어졌는지와 무관하게 호출별 승인을 요구한다(규칙 R2).

## 8. 배포 묶음

`deploy/`의 `compose.yaml`은 LiteLLM(MINT 설치 파생 이미지), PostgreSQL 16, 정책 엔진, 로컬 내구 버퍼용 명명 볼륨(`/var/lib/mint/buffer`)을 묶는다. 운영자 명령줄 도구는 같은 이미지의 `control` 서비스로 실행하며 `./mint.sh cli <명령>`으로 부를 수 있다.

| 명령 | 동작 |
| --- | --- |
| `./mint.sh up` | 이미지를 빌드하고 데이터베이스를 띄워 `init`(마이그레이션, 로그인 역할, 기본 조직, `config/litellm.mint.yaml` 생성)을 실행한 뒤 정책 엔진, LiteLLM, 작업 실행기, 관리자 콘솔을 띄운다. `.env`에 `MINT_LITELLM_KEY`가 비어 있고 비밀 폴더에 `control.key`가 없으면 마스터 키로 제어 평면 키를 한 번 만들어(`proxy_admin` 사용자 `mint-control`, `allowed_routes`는 `init`이 안내하는 경로만) `control.key`에 두고 `init`으로 도구 목록 면제 키까지 저장한다. 끝에는 다음에 할 명령을 안내한다. |
| `./mint.sh bootstrap <이름> <LiteLLM 사용자>` | 첫 관리자를 만들어 토큰을 비밀 폴더의 `operator.token`(0600)에 두고 기본 정책(`initial`)을 적용한다. 이후 `./mint.sh cli`와 `status`는 환경 변수 `MINT_OPERATOR_TOKEN`이 없을 때 이 파일을 쓴다. 운영자가 이미 있으면 거부한다. |
| `./mint.sh status` | 서비스 상태를 보이고, 운영자 토큰이 있으면 `status` 출력(할 일 포함)을, 없으면 토큰 없이 실행되는 `doctor` 출력을 보여 준다. |
| `./mint.sh backup` | MINT·LiteLLM 데이터베이스(`mint.sql`, `litellm.sql`), 정책 번들(`mint.tar.gz`), LiteLLM 설정(`litellm.config.yaml`)을 `backups/<시각>/`에 함께 모은다. 하나라도 비면 폴더를 지우고 실패한다. |
| `./mint.sh upgrade` | 이미지를 다시 빌드하고 마이그레이션을 적용한 뒤 LiteLLM, 작업 실행기, 관리자 콘솔을 다시 띄운다. |

접속 지점은 두 곳이다.

- **MCP 게이트웨이**: LiteLLM 포트(`MINT_LITELLM_PORT`, 기본 4000)의 `/mcp`. 클라이언트(Claude Code 등)는 이 주소를 MCP 서버로 등록하고 LiteLLM 키로 인증한다.
- **관리자 콘솔**: `MINT_CONSOLE_PORT`(기본 8080). 화면의 모든 시각은 `MINT_CONSOLE_TIME_ZONE`(IANA 시간대 이름, 기본 `Asia/Seoul`)으로 보인다. 세션 쿠키가 `Secure`라서 브라우저는 HTTPS로 열어야 로그인된다. TLS는 앞단(역방향 프록시, 또는 사내망이면 `tailscale serve --https=<포트> http://localhost:<콘솔 포트>` 같은 방식)에서 끝내고 이 포트로 전달한다. HTTP 주소로 직접 열면 로그인 응답의 쿠키를 브라우저가 저장하지 않는다.

한 기기에 스택을 여럿 둘 때는 `.env`의 `COMPOSE_PROJECT_NAME`을 스택마다 다르게 정한다. 컨테이너·볼륨 이름과 파생 이미지 태그(`mint-litellm:<프로젝트 이름>`)가 이 값으로 나뉘어 서로 덮어쓰지 않는다. 포트(`MINT_LITELLM_PORT`, `MINT_CONSOLE_PORT`)와 비밀 디렉터리(`MINT_SECRETS_DIR`)도 스택마다 다르게 둔다.

LiteLLM·작업 실행기·콘솔은 비루트 사용자(uid 65532)로 실행한다. 판정 버퍼(`/var/lib/mint/buffer`), 내보내기(`/var/lib/mint/export`), 정책 번들(`/bundles`) 볼륨은 이 사용자가 쓴다. 새로 만드는 볼륨은 이미지의 소유자를 물려받고, 이전 판본이 루트로 만든 볼륨은 `./mint.sh up`·`upgrade`가 소유자를 맞춘다. 운영자 명령줄 도구(`control`)는 호스트의 비밀 디렉터리에 쓰므로 루트로 실행한다. 계약 관측 주기는 `MINT_OBSERVE_SECONDS`(기본 3600초, 최소 20초)로 정하며 작업 실행기와 LiteLLM에 같은 값이 전달된다.

백업 폴더를 되돌리는 스크립트는 제공하지 않는다. 백업은 보존용이며, 데이터베이스·정책 번들·설정을 같은 시점으로 맞추고 정책 엔진의 판본이 데이터베이스의 활성 판본과 일치하는지 대조해야 한다. 데이터베이스를 되돌린 뒤의 확인과 해제는 `restore check`·`restore attest` 명령이 맡는다(`docs/CLI.md`).

호출별 승인의 인자 지문 키(`MINT_FINGERPRINT_KEY`, 무작위 32바이트의 base64url)는 `init`이 처음 한 번 생성해 저장소 밖 비밀 파일(기본 `~/.config/mint/secrets.env`, 권한 0600; `--secrets-file` 또는 `MINT_SECRETS_FILE`로 변경)에 `MINT_FINGERPRINT_KEY_VERSION`과 함께 기록한다. 이미 있는 키는 바꾸지 않으며, compose는 이 파일을 LiteLLM 서비스와 제어 평면 컨테이너에 환경 변수로 넘긴다. 키를 바꾸면 아직 소비되지 않은 호출별 승인의 지문이 맞지 않게 되므로 다시 요청해야 한다.

비밀 파일의 디렉터리는 `init`이 없으면 0700으로 만든다. 파일을 새로 만들 때뿐 아니라 이미 있는 파일을 읽을 때도(`init`의 재실행, 키를 읽는 명령) 마지막 디렉터리와 파일이 심볼릭 링크이거나, 디렉터리를 다른 사용자가 쓸 수 있거나, 파일의 권한이 0600이 아니면 자동으로 고치지 않고 실패한다. 검사는 열어 둔 디렉터리·파일 기술자 기준이다. 파일을 읽거나 해독하지 못해도 실패로 알린다.

파생 이미지의 진입점은 LiteLLM을 시작하기 전에 설정 파일을 검사하며, 설정 인자(`--config`, `--config=`, `-c`, `-c<경로>`)가 정확히 하나여야 한다. 설정을 환경 변수로 받는 `CONFIG_FILE_PATH`, `LITELLM_CONFIG_BUCKET_NAME`, `LITELLM_CONFIG_BUCKET_OBJECT_KEY`, `LITELLM_CONFIG_BUCKET_TYPE`는 LiteLLM이 인자보다 먼저 쓰므로 빈 값이라도 정의되어 있으면 시작하지 않는다. 둘 이상이거나 해석할 수 없는 형태이면 시작하지 않는다.

## 9. 지표

관리자 콘솔이 `/api/v1/metrics`에서 Prometheus 텍스트 형식으로 지표를 내보낸다. 별도 포트나 패키지가 필요 없고, 인증은 다른 API와 같은 운영자 토큰(`Authorization: Bearer`)이다. 값은 데이터베이스에서 읽으며 15초 안의 반복 수집은 같은 결과를 받는다. LiteLLM의 Prometheus 콜백과는 따로 동작하며, 수집기 설정에 이 주소와 토큰만 더하면 된다.

| 지표 | 종류 | 라벨 | 의미 |
| --- | --- | --- | --- |
| `mint_decisions_total` | counter | `result`, `server_id` | 호출 판정 수. `result`는 `allowed`(허용), `observed`(관측 통과), `blocked`(정책 차단), `pending_approval`(승인 대기), `contract_drift`(계약 변경 차단), `dependency_failure`(검사·기록 실패 차단). |
| `mint_call_results_total` | counter | `result` | 허용된 호출의 결과 수. `success`, `tool_error`(도구가 오류를 돌려줌), `output_blocked`(결과 차단), `unknown`(응답 없음, 부수효과를 알 수 없음). |
| `mint_decision_seconds` | histogram | `le` | MINT가 판정에 쓴 시간(초). 기록을 쓰기 전까지의 시간이다. |
| `mint_jobs_pending` | gauge | `kind` | 종류별 대기 작업 수. |
| `mint_jobs_oldest_pending_seconds` | gauge | `kind` | 종류별 가장 오래 기다린 작업의 대기 시간(초). |
| `mint_server_last_observed_age_seconds` | gauge | `server_id` | 서버별 마지막 계약 관측 성공 뒤 지난 시간(초). |
| `mint_alerts_open` | gauge | `kind`, `severity` | 해결되지 않은 경보 수. |

라벨에는 사용자·인자·도구 이름을 쓰지 않는다. `outcome`이 없는 이전 사건은 허용 아니면 정책 차단으로 센다.

### 결과 분류와 판정 참조

판정 사건과 응답 사건에는 새 행부터 `outcome`이 남는다. 연결(응답이 왔는가), 정책 판정, 도구 업무 성공(`isError`·JSON-RPC 오류), 독립 부수효과(응답이 없으면 알 수 없음)를 한 낱말로 줄인 값이며 콘솔 원장의 「결과」 열에 보인다. 정책이 막은 호출(`blocked`)과 검사·기록 부품이 실패해 막은 호출(`dependency_failure`)을 구분한다.

차단 응답의 `reference`는 원장에서 같은 호출을 찾는 값이다. 콘솔 원장의 「판정 참조」 칸이나 `GET /api/v1/ledger?ref=<참조>`에 넣으면 기간 제한 없이 그 호출의 사건을 보여 준다. 참조에는 비밀이나 정책 내부 값이 들어 있지 않다.
